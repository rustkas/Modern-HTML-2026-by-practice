**Глава 1. Документ как модель данных**

### Почему эта глава важна

Большинство разработчиков до сих пор воспринимают HTML как «язык для рисования страниц». В 2026 году такое понимание уже недостаточно. Современный HTML — это прежде всего **декларативная модель данных**, из которой браузер строит сразу несколько важных представлений:

- DOM (Document Object Model)
- Accessibility Tree
- Render Tree
- данные для поисковых систем и AI-агентов
- основу для Server-Side Rendering и гидратации

Именно от качества этой модели зависит доступность, производительность, SEO и удобство поддержки всего приложения. Поэтому мы начинаем создание FocusBoard не с дизайна и не с JavaScript, а с правильной модели документа.

### Что такое документ в современном HTML

Даже сложное веб-приложение остаётся **документом**.  
FocusBoard — это не «набор div-ов с логикой», а структурированный документ, который описывает:

- что является основным содержимым;
- где находится навигация;
- какие блоки являются самостоятельными сущностями (задача, заметка);
- какие элементы интерактивны;
- какую информацию нужно передать вспомогательным технологиям.

HTML отвечает на вопрос **«Что это?»**, а не **«Как это выглядит?»**.

### DOM как дерево данных

После загрузки HTML браузер превращает его в дерево объектов — DOM. Каждый тег становится узлом. Именно с этим деревом потом работают CSS, JavaScript, скринридеры и браузерные API.

Ключевые типы узлов, которые нам важны:

- `Document` — корень
- `Element` — HTML-элементы
- `Text` — текстовые узлы
- `DocumentFragment` — временные фрагменты (полезно при работе с шаблонами)

Правило, которое стоит запомнить сразу:

> Чем чище и осмысленнее HTML, тем проще, быстрее и надёжнее получается DOM.

### Семантика против оформления

Самая распространённая ошибка — выбирать элемент по тому, как он выглядит «из коробки».

Неправильно:
```html
<div class="header">...</div>
<div class="task">...</div>
```

Правильно:
```html
<header>...</header>
<article class="task">...</article>
```

Семантический элемент сразу сообщает браузеру, поисковику и скринридеру смысл блока. Это влияет на:

- Accessibility Tree (landmarks и роли)
- навигацию с клавиатуры и скринридеров
- SEO
- возможность использовать нативные API (например, `<dialog>`, `popover`, формы)

### Практическая задача главы

Создать семантический каркас FocusBoard.

#### Минимальная структура документа

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="description" content="FocusBoard 2026 — современная панель продуктивности">
  <title>FocusBoard 2026</title>
  <!-- стили подключим позже -->
</head>
<body>
  <header>
    <!-- шапка приложения -->
  </header>

  <nav aria-label="Основная навигация">
    <!-- навигация -->
  </nav>

  <main>
    <!-- основное содержимое -->
  </main>

  <aside>
    <!-- боковая панель (фильтры, быстрые действия) -->
  </aside>

  <footer>
    <!-- подвал -->
  </footer>
</body>
</html>
```

#### Разметка основных зон FocusBoard

```html
<header>
  <h1>FocusBoard</h1>
  <p>Персональная панель продуктивности</p>
</header>

<nav aria-label="Основная навигация">
  <ul>
    <li><a href="#tasks">Задачи</a></li>
    <li><a href="#notes">Заметки</a></li>
    <li><a href="#settings">Настройки</a></li>
  </ul>
</nav>

<main id="tasks">
  <h2>Задачи</h2>
  <!-- здесь позже появятся задачи -->
</main>

<aside aria-label="Фильтры и быстрые действия">
  <h2>Фильтры</h2>
  <!-- фильтры -->
</aside>

<footer>
  <p>FocusBoard 2026</p>
</footer>
```

### Важные правила, которые мы фиксируем сразу

1. На странице должен быть **только один** активный `<main>`.
2. `<header>` и `<footer>` на верхнем уровне документа становятся landmarks (`banner` и `contentinfo`).
3. Если `<header>` или `<footer>` находятся внутри `<article>` или `<section>`, они теряют роль landmark.
4. Заголовки (`h1`–`h6`) должны образовывать логическую иерархию. Не полагайтесь на старый outline-algorithm — его больше нет.
5. Каждый важный раздел по возможности должен иметь доступное имя (через видимый заголовок + `aria-labelledby` или `aria-label`).

### Типичные ошибки, которых нужно избегать

- Использовать `<div>` и `<span>` там, где есть подходящий семантический элемент.
- Делать несколько `<main>` на одной странице.
- Пропускать `lang` у элемента `<html>`.
- Ставить `h1` в каждом блоке «для красоты».
- Игнорировать необходимость доступных имён у landmarks.

### Что должно получиться в конце главы

После выполнения заданий у вас должен быть файл `index.html` с:

- корректным `<!DOCTYPE html>` и `lang="ru"`;
- обязательными meta-тегами;
- семантическим каркасом FocusBoard;
- правильными landmarks;
- логичной иерархией заголовков;
- заготовками основных разделов приложения.

Это и есть фундамент, на который мы будем надстраивать всю остальную функциональность.

### Задания для закрепления

1. Создайте файл `index.html` с полной семантической структурой FocusBoard.
2. Проверьте страницу в DevTools → Accessibility. Убедитесь, что landmarks определяются правильно.
3. Добавьте внутрь `<main>` два-три будущих блока задач с использованием `<article>`.
4. Сформулируйте в комментарии, почему вы выбрали именно эти элементы, а не `<div>`.
